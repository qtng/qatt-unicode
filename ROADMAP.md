# Roadmap

Plan for resolving the open points in section 9 of the proposal. The source work comes first, because almost every other decision depends on it.

## Phase A – Sources (evidence catalogue)

Record each passage in [evidence/catalog.csv](evidence/catalog.csv).

1. Function of the components: initial and rhyme in phản thiết pairs and Hợp Thư, rhyme extension in Tham Thư (E06, E08, E11). Main argument for the encoding model.
2. Standalone and adjacent components (E04). Main argument for the explicit joiner.
3. Scope of the term Hợp Thư and the omission convention (E07, E09).
4. Both Tham Thư, phản thiết examples, tone marks in all four corners (E05, E10–E16).
5. Layout of the components within a cell (proposal 4.5), from the same examples.
6. Date, provenance and location of both sources; scholarly literature (E17–E21).

## Phase B – Names and order

1. Names of the 22 Cán Tự, starting from the letter names in the QATT description code (Ɂ, B, C, Ch, …); ASCII name for Ɂ.
2. Which marking-stroke position belongs to the Cán Tự, and the names and order of the five Chi Tự positions. Gives the code point order (proposal 6.4).
3. Final name of the component joiner.

## Phase C – Justification

1. Reasons for encoding and modern use (proposal 2.2, 3.3), including documented written forms from online discussion (E22).
2. Decision in proposal 5.8: Tham Thư combiner now or later, once the strength of the Tham Thư evidence is known.

## Phase D – Technical

1. Draft Unicode Character Database entries (UnicodeData.txt fields, grapheme cluster break, line break, bidi, vertical orientation, East Asian width) and a list of questions for the Unicode text-segmentation experts.
2. Reference font and code chart glyphs: check existing QATT glyphs; designer and licence to be decided.
3. Horizontal use: record as an assumption rather than an open point.

## Phase E – Submission

1. Proposer details and the UTC Proposal Summary Form.
2. Check the Unicode roadmap for the Supplementary Multilingual Plane; the block position is assigned by the UTC.
3. Pre-submission review by the Script Encoding Initiative (UC Berkeley).
